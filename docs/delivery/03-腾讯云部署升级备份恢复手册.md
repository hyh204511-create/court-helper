# 法院立案/强执查询助手

## 腾讯云部署、升级、备份与恢复手册

版本：0.2.0
生产域名：`court.hyhbrand.xyz`
服务器：腾讯云轻量应用服务器，Ubuntu 24.04

> 本系统是单实例部署，不提供自动跨机故障转移。生产凭据、证书私钥和备份解密私钥必须通过客户受控密码库交接。

## 1. 网络与 DNS

1. 为 `court.hyhbrand.xyz` 创建 A 记录，指向轻量服务器公网 IP。
2. 腾讯云防火墙只允许公网 TCP 80/443；TCP 22 仅允许固定运维 IP。
3. 操作系统防火墙采用相同边界；不要开放 3000、5432、8765。
4. 确认 DNS 生效后申请可信 Nginx 证书，放入：
   - `server/deploy/certs/fullchain.pem`
   - `server/deploy/certs/privkey.pem`

## 2. 主机初始化

```bash
sudo apt update
sudo apt install -y ca-certificates curl age
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"
docker version
docker compose version
```

重新登录 SSH 使 docker 组生效。生产目录固定为 `/opt/court-helper/releases/<version>`，当前版本链接为 `/opt/court-helper/current`。

## 3. 环境变量

1. 将 `server/.env.production.example` 复制为 `server/.env`。
2. 生成 32 字节 Base64 主密钥：`openssl rand -base64 32`。
3. 设置强 PostgreSQL 密码和一次性管理员密码。
4. 把 `REPLACE_WITH_FIXED_EXTENSION_ID` 换成交付清单中的固定扩展 ID。
5. 保持 `LOCAL_STORAGE_DIR=/var/lib/court-helper/storage`，所有 `OBJECT_STORAGE_*` 留空。
6. 执行 `chmod 600 server/.env server/deploy/certs/privkey.pem`。

> 用户级 `DATABASE_URL` 可能指向其他项目。生产只通过 Compose 的 `server/.env` 启动，数据库名必须为 `courthelper`，禁止连接 assistant 库。

## 4. 首次部署

```bash
sudo mkdir -p /opt/court-helper/releases
sudo unzip court-helper-0.2.0-delivery.zip -d /opt/court-helper/releases
sudo mv /opt/court-helper/releases/court-helper-0.2.0-delivery /opt/court-helper/releases/0.2.0
sudo ln -sfn /opt/court-helper/releases/0.2.0 /opt/court-helper/current
cd /opt/court-helper/current/server
sudo chmod +x deploy/scripts/*.sh
sudo ./deploy/scripts/deploy.sh
```

验收：

- `docker compose --profile tls ps` 中 db、app、nginx 正常。
- `curl -fsS https://court.hyhbrand.xyz/health` 返回 `{"ok":true}`。
- HTTP 自动跳转 HTTPS，浏览器证书可信。
- 3000、5432 从公网不可访问。
- 初始管理员登录后立即改密码。

## 5. 日常检查

```bash
cd /opt/court-helper/current/server
docker compose --profile tls ps
docker compose logs --tail=100 app nginx
curl -fsS https://court.hyhbrand.xyz/health
df -h
docker system df
```

日志只用于定位请求 ID、路由、状态码和耗时。不要启用包含查询 URL 的 Nginx access log，不要输出请求体、响应体、凭据、截图或驳回原因。

## 6. 加密备份到私有 COS

1. 创建客户控制的私有 COS 桶，禁止公有读，并设置不超过 30 天的生命周期。
2. 创建仅能向备份前缀写入/读取/删除的最小权限凭据，配置 `coscli`。
3. 在受控密码库保存 age 解密私钥；服务器只保存公钥 `BACKUP_AGE_RECIPIENT`。
4. 配置 `COS_BACKUP_URI=cos://<私有桶>/<备份前缀>`。
5. 将 `BACKUP_AGE_RECIPIENT` 和 `COS_BACKUP_URI` 写入权限为 600 的 `server/.env`。
6. 每日运行 `server/deploy/scripts/backup.sh`，并监控退出码。

备份包含 PostgreSQL dump 和私有存储卷，上传前已使用 age 加密。腾讯云快照只用于发布前短期回退，不能替代应用一致性备份。

## 7. 恢复演练

1. 先运行隔离演练脚本；它使用独立 Compose 项目、临时卷和临时明文目录，结束后自动销毁：

```bash
sudo ./deploy/scripts/restore-rehearsal.sh backup.tar.age age-identity.txt
```

2. 确认演练输出健康检查通过，且只用脱敏记录核对恢复结果。
3. 从 COS 下载 `.tar.age`，使用客户保管的 age 私钥解密。
4. 核对恢复目标、当前备份和回退方案。
5. 只有正式灾难恢复才运行：

```bash
sudo ./deploy/scripts/restore.sh --confirm-production-restore backup.tar.age age-identity.txt
```

6. 恢复后运行健康检查，并用脱敏记录核对数据库、截图和报表；确认后销毁明文临时文件。

## 8. 升级与回滚

升级前：完成加密备份、创建短期快照、阅读版本说明。

```bash
sudo /opt/court-helper/current/server/deploy/scripts/upgrade.sh /opt/court-helper/releases/0.2.1
```

如果健康检查失败：

```bash
sudo /opt/court-helper/current/server/deploy/scripts/rollback.sh 0.2.0
```

迁移脚本必须幂等。若新版本包含不可逆数据库变化，必须先按该版本说明恢复备份，不能只切换代码目录。

## 9. 证书更新

1. 在腾讯云 SSL 证书控制台下载新的 Nginx 证书。
2. 备份旧证书，替换 `fullchain.pem` 和 `privkey.pem`，私钥权限保持 600。
3. 执行 `docker compose --profile tls exec -T nginx nginx -t`。
4. 执行 `docker compose --profile tls restart nginx`。
5. 从外部浏览器核对证书域名、有效期和完整链。
