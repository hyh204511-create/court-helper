# 规格：admin-ui-module（轻量后台页面）

> 版本：1.0 ｜ 状态：已确认、待实现 ｜ 依据：server-module 0.1、Phase 11 控制台唯一入口决策、用户确认一键查询并导出
> v0.2 变更：固定控制台入口与登录跳转；拆分平台账号自动登录区和通用任务区；补充完整会话用户名、任务创建者与凭据按需查看；移除平台账号页重复登录入口。
> v0.3 变更：通用任务区移除三个独立任务选项，只保留一次提交的“一键查询并导出”；服务端创建单一 `QUERY_ALL_EXPORT` 命令。
> v0.4 变更：账号查询增加原告/被告/案号关键词过滤；登录和采集仍由控制台统一入口完成，关键词只用于本次台账读取，不进入浏览器命令或任务结果。
> v0.5 变更：控制台按账号分页读取案件后在页面内存中应用关键词，避免业务关键词进入请求 URL、代理访问日志或持久化状态；新查询只允许最新请求渲染。
> v0.6 变更：平台登录账号使用可输入搜索的账号标签框与 `datalist`；仅展示启用账号，提交和凭据查看均将标签解析为不透明 `platformAccountId`，不改变 `LOGIN` 命令负载。
> v0.7 变更：平台登录账号改为输入框、原生清空叉号和独立下拉按钮并存；下拉菜单始终展示启用账号，可直接替换当前输入值。
> v0.9 变更：一键查询并导出区的平台账号也改为可输入筛选的账号标签框，保留原生清空叉号和独立下拉按钮；仅展示启用账号，提交时将精确标签或唯一部分匹配解析为不透明 `platformAccountId`，无匹配或多项匹配必须拒绝提交。
> v1.0 变更：后台全页面统一为蓝白灰稳健政企视觉；桌面侧栏固定、小屏改为可访问抽屉；统一表单、表格和按钮层级。业务 API、权限、路由、DOM 行为钩子与安全契约保持不变。
> v1.1 变更：报表导出记录绑定平台账号，支持账号筛选并从成功记录进入同账号案件台账；页面不展示工作簿内凭据。
> v1.2 变更：一键查询并导出区增加必填的业务员自由文本输入；该值只用于本次报表 U 列，不作为平台账号、案件或凭据来源。
> v1.3 变更：案件台账、报表导出记录和平台账号管理列表的账号筛选统一为“可手动输入 + 独立下拉按钮”的标签选择器；案件与报表筛选只在精确标签或唯一部分匹配时解析为不透明 `platformAccountId`，空输入保留“全部账号”，歧义或无匹配不得发起带账号条件的请求。
> v1.4 变更：案件台账成为唯一案件结果视图，浏览器控制移除重复的“账号查询与案件状态”；台账拆分“案件状态”和“处理状态”，且不再默认用立案日期过滤无立案日期的审核中或待人工记录。

## 1. 目标与形态

后台是 `server-module` 同源托管的轻量页面，不新增前端服务：登录后完成系统账号管理、平台账号管理、导入模板上传/完整内容查看、浏览器任务控制、案件查看和截图查看/下载。

- 路由统一在 `/admin`；使用服务端 HTML + 少量 TypeScript/原生模块脚本，不引入独立 SPA 框架或第二容器。`/`、`/admin` 与登录成功后的唯一业务落点均为 `/admin/browser-control`。
- 页面只调用 `/api/v1`；会话使用 HttpOnly Cookie，脚本不可读取 token。登录校验同源 Origin，登录后的写请求携带仅存内存的 CSRF token。
- 案件页可见时每 3–5 秒轮询；页面隐藏时停止，失败时显示“服务器不可达，请重试”和手动重试按钮，不展示旧数据为“最新”。

### 1.1 视觉与响应式契约（v1.0）

- 视觉采用稳健政企风格：固定深蓝侧栏 `#0B2A4A`、主操作蓝 `#1677FF`、页面背景 `#F4F7FB`、白色内容面板、浅灰边框和深灰正文。页面仅使用本地中文无衬线字体，不加载外部字体、图标库、组件库或 CDN。
- 桌面端（宽度大于 `960px`）侧栏约 `264px` 宽，固定占满视口并允许自身纵向溢出；主内容预留等宽左侧空间，滚动业务内容时导航位置不得变化。内容区维持单一页面纵向滚动，宽表格只允许在各自 `.table-wrap` 内横向滚动。
- `960px` 及以下侧栏转为遮罩抽屉。页面必须提供带 `aria-controls`、`aria-expanded` 和可辨识名称的菜单按钮；点击菜单按钮、遮罩、任一导航链接或按 `Escape` 均可关闭抽屉，关闭后焦点返回菜单按钮。抽屉打开时阻止背景页面滚动。
- 菜单的角色隔离、链接目标与 `aria-current` 保持现有契约；小屏抽屉只是导航呈现变化，不新增或隐藏业务入口。
- 控件使用 4/8px 间距体系、8–12px 圆角和克制阴影；主要触控控件有效高度不低于 `44px`。输入、选择、按钮必须有清晰的 hover、focus-visible、pressed、disabled 状态，正文颜色对比度满足 WCAG AA。
- 动效只用于抽屉、遮罩和交互状态反馈，时长控制在 150–240ms，且在 `prefers-reduced-motion: reduce` 下关闭非必要过渡。
- 页面按钮按所属功能区就近分层：主操作使用主色按钮，刷新、返回、关闭等次操作使用描边按钮，删除设备、删除报表、清空任务等危险操作使用红色并与主操作保持视觉和空间隔离。按钮仍保留在原表单作用域内，不改变既有 ID、提交事件、忙碌禁用或二次确认逻辑。
- `/admin/login`、所有受保护页面、案件详情和 403 页面共享同一色彩、字体、圆角和焦点体系；登录页采用深蓝品牌区与白色登录表单组合。

## 2. 页面与核心交互

| 页面 | 角色 | 核心契约 |
|---|---|---|
| `/admin/login` | 未登录 | 用户名 + 密码登录；错误统一显示“账号或密码错误/账号不可用”，不区分账号是否存在；成功进入 `/admin/browser-control` |
| `/admin/users` | admin | 系统用户列表、创建、改名、改角色、启停、软删除、重置密码；密码仅创建/重置时输入且不回显 |
| `/admin/platform-accounts` | admin | 平台账号标签、状态、更新时间的增删改查与启停；创建/编辑可写入或替换账号密码，提交后立即清空输入；账号列表可按标签手动输入筛选或从独立下拉菜单选择；不提供“远程登录”按钮或登录指令列表 |
| `/admin/browser-control` | admin,user | 后台唯一任务操作入口：显示完整当前后台用户名；上传 xlsx 建立受控批次、查看/下载完整上传文件；在“平台账号与自动登录”区选择启用账号并创建 LOGIN；在一键任务区选择平台账号和空白批次并创建 `QUERY_ALL_EXPORT`；显示任务所属平台账号标签与完整创建者名称；查看任务进度/结果、取消或重试；可二次确认后清空当前用户有权查看的已结束任务记录；按需查看完整平台账号密码；提供进入案件台账的明确链接但不重复读取或渲染案件状态 |
| `/admin/cases` | admin,user | 唯一案件结果视图；查看保留期内案件，按类型、精确案件状态、可输入的平台账号标签、待人工处理状态、可选立案日期筛选，游标分页；显示原告、被告、案件状态、处理状态、案号、驳回原因与查询时间 |
| `/admin/cases/:id` | admin,user | 案件完整只读详情；UNKNOWN 明确标“待人工”，不得由页面推断或改写状态 |
| `/admin/report-exports` | admin,user | 仅显示服务端上传成功的报表记录：平台账号标签、文件名、大小、SHA256 前 8 位、导出人、导出时间；支持手动输入账号标签或从独立下拉菜单筛选、进入同账号案件台账、鉴权下载或删除；页面不展示工作簿内账号密码 |
| 案件详情截图区 | admin,user | 展示成功/驳回截图缩略图；点击鉴权查看，提供下载按钮；DOM 和地址栏不暴露桶名、对象键或签名参数持久值 |

- 删除系统用户/平台账号均为软删除并二次确认；最后一个启用的 admin 不显示可执行的停用、删除或降级操作，服务器仍须强制校验。
- 平台账号凭据字段用 `autocomplete="new-password"`，编辑时只显示“已设置/未设置”；完整账号密码仅在用户显式点击查看时从同源专用 API 读取，渲染为纯文本，关闭/切页即清空，不写入 localStorage/sessionStorage、URL、任务 payload 或客户端日志。
- 控制台当前后台用户名和任务创建者名称使用完整 `username` 纯文本展示，不调用掩码函数；user 只看本人任务，admin 可通过既有用户列表映射全部创建者。该名称映射不得下放给 extension Bearer。
- “一键登录”与一键查询导出表单必须独立：登录表单只创建 `LOGIN`；查询导出表单不得包含任务类型选择器，只允许创建 `QUERY_ALL_EXPORT`。账号和导入批次均必选；一键查询导出账号使用与登录账号一致的可输入选择器，可按标签大小写不敏感筛选，也可用独立下拉按钮查看全部启用账号；精确标签优先，只有一个部分匹配时才允许提交，无匹配或多项匹配时提示从启用账号中选择。提交期间按钮禁用，重复点击由服务端活动任务唯一约束兜底。
- 案件台账与报表导出记录的账号筛选使用同一交互：输入框允许手动键入标签，独立下拉按钮可展开全部可见平台账号；空输入表示全部账号，非空输入按大小写不敏感的精确标签优先、唯一部分匹配兜底解析。无匹配或多项匹配时页面须提示并停止本次筛选，不得把标签明文或错误 UUID 写入查询参数。平台账号管理列表使用同类输入与下拉，但只在当前页面内按标签子串过滤行，不新增服务端搜索参数，也不影响新增/编辑凭据表单。
- 上传模板完整内容仅在用户显式打开/下载时读取；页面不持久化文件字节或解析后的业务明文。
- 案件和截图只读；列表轮询保留当前筛选、分页与选中案件，不自动跳页。
- 案件台账是唯一读取和渲染案件列表 API 的后台页面；浏览器控制不得再实现账号案件查询、案件分页或案件状态表格，只提供进入 `/admin/cases` 的链接。任务列表状态与案件业务状态严格分离，页面不得从任务成功、结果摘要或账号标签推断案件是否立案成功。
- 案件台账将服务端 `status` 原样作为“案件状态”事实展示，`UNKNOWN` 显示“待人工确认”；另以 `needsHuman` 显示独立“处理状态”（待人工/正常），不得因已确认的案件状态为成功或驳回而隐藏待人工处理标记。`errorCode` 仅允许经稳定中文映射后辅助显示，不得回显原始业务明文。
- 案件台账进入页面时不得自动填写立案日期起止条件。服务端保留期已经约束可见数据；显式日期筛选仍只表示立案日期，不得借“近 30 天”名义默认排除 `filedTime=null` 的审核中、驳回或待人工记录。
- “清空任务记录”仅物理删除当前会话有权查看范围内的**已结束** `browser_commands`（`succeeded/failed/expired/manual_required/cancelled`）；`pending/executing` 必须保留。admin 清理全部可见已结束任务，user 只清理本人创建的已结束任务。操作须二次确认、携带 CSRF、防重复提交，并显示实际删除条数；不删除案件、截图、导入批次、报表或平台账号。

## 3. 角色隔离

| 能力 | admin | user |
|---|:---:|:---:|
| 登录、退出、查看本人信息 | ✓ | ✓ |
| 系统用户 CRUD/启停/重置密码/角色 | ✓ | — |
| 平台账号 CRUD/启停/替换凭据 | ✓ | — |
| 查看完整平台账号/密码（同源后台 no-store） | ✓ | ✓ |
| 上传、查看和下载完整导入模板 | ✓ | ✓ |
| 创建/查看/取消/重试浏览器任务 | ✓ | ✓ |
| 案件与截图查看/下载 | ✓ | ✓ |
| 报表导出记录查看/下载/删除（user 仅本人） | ✓ | ✓ |

- user 不渲染管理导航；直接访问管理路由跳转到 403 页面。API 返回 403 是最终权限边界，前端隐藏不能替代服务端鉴权。
- 退出、用户停用、删除或密码重置后，已打开页面的下一次请求必须转到登录页，不继续显示受保护详情。

## 4. 状态、错误与安全显示

- 表单做必填、长度和一致性校验；服务端 `error.code` 决定提示，未知错误只显示 request ID，不显示栈、SQL、路径或原始响应。
- 保存按钮提交期间禁用，成功后重新拉取服务器数据；超时/失败不得乐观显示成功。破坏性操作必须确认且防重复提交。
- 截图经受权内容 API 获取，前端不缓存永久 URL；下载文件名使用脱敏、服务器生成的安全名称。
- 凭据和模板明文查看 API 只接受 `admin_ui` Cookie 会话；请求带 `Origin` 时必须精确匹配后台同源 Origin，跨域 Origin 拒绝。响应 `Cache-Control: private, no-store`；未登录、extension Bearer、普通列表及轮询响应不得出现明文。完整账号密码/文件内容不进入 URL、任务 payload、报错消息、分析埋点或日志。
- HTML 启用严格 CSP；所有业务文本按纯文本渲染，驳回原因不得作为 HTML 注入。页面不埋点、不接第三方 CDN。

## 5. 验收门槛

1. admin、user、禁用用户分别验证登录/退出；Cookie 为 HttpOnly + Secure + SameSite=Strict，写请求无/错 CSRF token 被拒绝。
2. admin 可完成系统用户 CRUD、启停、角色调整和重置密码；最后一个 admin 受保护；user 的页面入口和直接 API 均无管理权限。
3. admin 可管理平台账号并替换凭据，且平台账号页无远程登录入口；admin、user 均可在控制台通过同源 no-store 专用接口显式查看脱敏测试账号密码；extension Bearer、未登录、跨域 Origin、普通 API 响应、页面持久化状态和服务日志均不得出现该明文。
4. `/`、`/admin` 与登录成功均进入 `/admin/browser-control`；控制台显示完整当前后台用户名、任务所属平台账号标签和任务创建者名称；“一键登录”创建 LOGIN，一键查询导出区只创建 `QUERY_ALL_EXPORT` 且不显示独立立案/强执/导出选项。一键查询导出账号框可输入筛选、原生清空或展开全部启用账号，精确标签和唯一部分匹配均提交对应的不透明账号 ID，歧义或无匹配不创建任务。业务员为必填自由文本，首尾空白清理后随命令提交，空白或超过 100 个字符不创建任务；导出报表每条业务数据行的 U 列均显示该值。控制台不请求或渲染案件状态，只提供案件台账入口；清空操作只删除权限范围内的已结束任务并返回删除条数，活动任务和案件证据保持不变。
5. admin、user 均可上传、列出并显式查看/下载脱敏模板；扩展只按已领取命令读取必要批次执行数据，不获得后台明文查看能力。
6. 两级角色均可在唯一案件台账筛选、分页、查看案件与授权截图；首次进入不携带默认立案日期条件；案件状态与处理状态分列，已确认状态且 `needsHuman=true` 时仍明确显示待人工，`UNKNOWN` 不伪装为成功；未授权截图请求被拒绝，下载可用。
7. 轮询间隔在 3–5 秒，隐藏页停止；断网/503 明确提示重试且不伪装为最新；恢复后可手动重试。
8. 使用脱敏 fixture 做页面与 API 集成测试；测试截图来自 fixture，禁止使用真实案号、当事人、账号、密码或截图。
9. 案件台账、报表导出和平台账号列表的账号筛选均同时覆盖手动输入、下拉选择、清空后查看全部、唯一部分匹配以及歧义/无匹配拒绝；案件与报表请求只携带解析后的 `platformAccountId`，平台账号列表筛选不发额外业务请求。
10. 报表导出页：列表展示与权限过滤正确（user 不见他人记录）；下载返回原文件且不暴露 object_key；删除后记录消失。
11. 1600×900 与 1366×768 视口滚动页面时侧栏边界保持不变，主内容不被侧栏覆盖；390×844 视口使用抽屉，无整页横向滚动，表单和按钮保持可操作。
12. 小屏导航按钮、遮罩、导航链接和 `Escape` 均能关闭抽屉，`aria-expanded` 与可见状态同步，关闭后焦点回到菜单按钮；键盘 Tab 顺序与视觉顺序一致。
13. v1.0 改版不得改变任何 `/api/v1` 请求、角色权限、路由、表单字段、DOM 行为钩子、轮询、凭据清理、文件操作或危险操作确认；既有后台 UI 集成测试须全部继续通过。

## 6. 范围外（不做）

- 不做多租户、组织切换、四级 RBAC、自定义权限、SSO 或用户自助注册/找回密码。
- 不做密钥管理页面或凭据租约页面；平台明文查看范围以本规格明确的已登录后台用户为准。
- 不做案件编辑/删除、人工审核流、统计图表、服务器端 Excel 生成、通知中心、操作审计中心（控制页清空仅作用于已结束任务历史；后台只私有保存/解析上传模板，报表文件仍由扩展本地生成后上传）。
- 不做 SSE/WebSocket 实时推送、离线缓存/PWA、移动端 App、独立前端部署或第三方前端资源。
- 不做深色模式、桌面侧栏手动收缩、SPA 路由、外部字体、外部图标库或对既有业务流程的重新编排。
## 7. 历史物理删除（v0.8）

- 一键查询并导出任务支持逐条删除和二次确认的一键批量删除；只删除已结束 `QUERY_ALL_EXPORT`，删除后重新加载任务接口不再返回该行。
- 管理员可逐条删除或一键删除已授权设备；服务端先撤销设备会话并取消未完成配对，再物理删除设备记录，重新加载授权接口不得继续显示已删除设备。
