# 规格：app-module（扩展执行器、Options/Setup 与批量任务执行器）

> 版本：0.2 ｜ 状态：已确认、待实现 ｜ 依据：用户需求（导入/导出/软件查询/每日新案处理）、Phase 11 控制台唯一入口决策
> v0.2 变更：后台控制台取代 Popup 业务界面；删除 Popup 源码/产物/测试；扩展 action 按授权状态路由控制台或独立 Options/Setup；批量执行器继续由统一 browser command 驱动。

## 1. 目标

后台 `/admin/browser-control` 是导入、登录、查询和导出的唯一业务操作台。扩展不再提供 Popup，只保留 Service Worker、content 执行器、状态型浮动面板以及独立 Options/Setup 配对页；批量执行器继续负责真实法院页面上的节流查询、状态识别、截图、IndexedDB 和导出链路。

## 2. 入口与界面边界

```
扩展 action 点击
├─ serverUrl 已配置 + 配对 token 有效 → 打开 http://127.0.0.1:3000/admin/browser-control
└─ 未配置 / 未配对 / 已过期 / 已撤销 → chrome.runtime.openOptionsPage()
```

- manifest `action` 不含 `default_popup`；`extension/popup/`、`extension/dist/popup.bundle.js`、popup 构建命令与 popup 专用测试必须不存在。
- 独立 Options/Setup 页面只包含：服务地址、请求后台授权、六位核对码、配对/授权状态。不得出现平台账号选择、账号密码、登录、导入、查询、导出、案件结果或本地搜索。
- Options/Setup 仅接受规范化根地址 `http://127.0.0.1:3000`；不增加 `<all_urls>`，host 权限继续限定 `http://127.0.0.1:3000/*`。
- 后台控制台通过 `LOGIN` / `QUERY_LI` / `QUERY_QZ` / `EXPORT_REPORT` 统一命令触发执行；浮动面板只展示脱敏状态、进度和人工接管提示。
- 列表页判定 = 网上立案列表（`#/pagesWsla/pc/list/index`）或「我的案件」页（`#/pages/pc/case-list/index`），两路由均可执行已领取批量查询。

## 3. 软件查询（本地检索）

- 本地 IndexedDB 检索能力作为执行器/既有数据层保留，不再暴露为 Popup UI；后台案件页承担操作人员查询入口。
- 内部检索支持账号或客户名（原告/被告）模糊匹配及状态筛选（全部/审核中/立案成功/已驳回/强执成功/UNKNOWN）。
- 查询 IndexedDB 的 `cases` + `enforcementCases`，合并展示（类型列区分 立案/强执）。
- 展示字段：账号（脱敏）、原告、被告、状态、成功时间、案号、驳回时间、驳回原因（截断+悬停全文）、截图缩略图、查询时间。
- 查询时间 < 1s，纯本地，不请求平台。

## 4. 批量任务执行器（核心）

### 4.1 任务来源与分组
- 任务 = 后台上传的受控 `importBatchId` 中待查询行；扩展仅在成功领取对应 browser command 后读取执行数据。
- 查询类型由 `QUERY_LI` / `QUERY_QZ` 决定；SW 向 content 发送既有 `START_BATCH`（`kind=li/qz`），content 按 kind 选 store（既有 `startBatch(kind)`）。
- **强执不自动切 tab**：强执批量要求用户当前停在页面顶部「执行」tab（采集器按行内 caseType 识别状态）；非执行 tab 下启动强执 → 明确提示切换。
- 按账号分组；**当前登录账号匹配到的分组为「可执行」**（与 login-module 当前账号比对 C 列）；其余分组标记「待切换账号」。

### 4.2 执行流程（单条）
```
定位该账号在平台中的案件行（列表采集器，翻页上限 10）
→ 状态识别（query-module 映射表）
→ 待审核：写状态=审核中 + queryTime=当天，不截图
→ 成功/驳回：进入详情采集 → 截图（screen-capturer）
→ 写 IndexedDB（唯一键 upsert）
→ 下一条（间隔 3–8s 随机）
```

### 4.3 控制与失败处理
- 单批上限 50 条；批间需人工确认继续。
- 失败重试 1 次（同一条）；仍失败 → 标记「待人工」并跳过，不阻塞后续。
- 会话失效事件 → 立即暂停队列，提示重新登录；恢复登录后从暂停点继续。
- `SELECTOR_CHANGED` → 暂停，提示更新选择器配置。
- 暂停/继续与人工接管由统一命令状态和既有执行器控制；暂停点落盘（chrome.storage.local），SW 休眠或后台页面关闭后任务状态仍可恢复。
- 进度展示：当前条目（账号+客户名脱敏）、已完成/总数、失败数。

### 4.4 账号切换衔接
- 当前账号分组执行完毕 → 后台任务状态与浮动面板提示需要切换账号/人工接管。
- 插件检测到登录账号变化（login-module）→ 自动切换到新账号分组继续（若在等待继续状态）。

## 5. 每日流程（用户操作闭环）

1. 操作人员登录后台控制台；未配对时在 Options/Setup 完成服务地址配置与设备授权。
2. 控制台上传当天新案件模板，服务器生成受控批次并展示脱敏摘要。
3. 控制台选择启用平台账号并点击“一键登录”，创建 `LOGIN`；查询区创建 `QUERY_LI` 或 `QUERY_QZ`。
4. 扩展执行已领取命令；中途按控制台/浮动面板提示切换账号或人工接管。
5. 控制台创建 `EXPORT_REPORT`；扩展生成 `立案与强执查询表-<日期>.xlsx`、本地下载并上传，后台「报表导出」可再次下载；上传失败不得伪造成功（详见 report-export-module）。
6. 后台案件页核对历史记录。

## 6. 测试

- 单测：任务分组（按账号）、节流调度（间隔范围断言）、暂停/继续状态机、失败重试与「待人工」标记、唯一键 upsert。
- simulator 集成：mock 平台页 + fake IndexedDB（node 环境）跑通「受控批次→统一命令→批量查询→写库→导出」链路。
- manifest/action/Setup：无 `default_popup` 和 popup 文件引用；已授权点击图标打开控制台；未授权打开 Options/Setup；Setup 只渲染服务地址、六位核对码与授权状态。
- 真实联调（验收闸门）：用户已登录真实会话，全流程走查 2–3 条真实案件，验收记录只写脱敏摘要。

## 7. 范围外（不做）

- 不做 Popup 或页面内第二套业务控制台；不保留 Popup 兼容入口。
- 不做定时/自动执行（无 cron、无后台定时批量）——每天由操作人员在后台控制台手动触发。
- 不做无人值守账号自动切换或绕过统一命令的登录；自动登录只能由后台控制台显式创建 `LOGIN` 命令，并沿 login-module 的单次重试/待人工边界执行。
- 不在扩展侧新增权限体系或服务器端法院 API/DOM 访问；后台权限与远程同步按 server/admin/browser-command 规格执行。
- 不增加 `<all_urls>` 或扩大法院站点、本机 OCR、本机后台以外的 host 权限。
- 不做平台消息推送/通知中心。
- 不做数据统计图表（报表仅导出模板格式）。
