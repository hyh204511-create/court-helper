# 规格：app-module（popup 界面、软件查询、批量任务执行器）

> 版本：0.1 ｜ 状态：待实现 ｜ 依据：用户需求（导入/导出/软件查询/每日新案处理）、计划 §Phase 6

## 1. 目标

popup 是插件的操作台：导入模板 → 按账号批量查询 → 查询结果展示 → 导出报表；支持按账号/客户名/状态软件内查询；管理每日新案件处理流程。

## 2. popup 布局

```
┌────────────────────────────────────┐
│ 法院立案/强执查询助手        [状态] │  ← 未登录/已登录(账号xxx)
│ ────────────────────────────────── │
│ [导入模板] [导出报表] [开始查询▾]   │  ← 类型：立案/强执（查询前选择）
│ ────────────────────────────────── │
│ 搜索: [账号/客户名________] [查]   │  ← 软件查询（本地 IndexedDB）
│ 状态筛选: [全部▾]                  │
│ ┌────────────────────────────────┐ │
│ │ 结果表: 账号|客户名|类型|状态|  │ │
│ │ 成功时间|案号|截图缩略|操作      │ │
│ └────────────────────────────────┘ │
│ ────────────────────────────────── │
│ 批量任务: [进度条 12/50] [暂停/继续]│
│ 待处理: 账号A(3条) 账号B(2条)...   │
└────────────────────────────────────┘
```

- 结果表行操作：查看截图（点击缩略图放大）、标记「待人工」备注。
- 未登录时「开始查询」禁用；已登录时显示脱敏账号并解锁。
- 列表页判定 = 网上立案列表（`#/pagesWsla/pc/list/index`）或「我的案件」页（`#/pages/pc/case-list/index`），两路由均可开始批量（挂真实平台门禁，query-gate）。

## 3. 软件查询（本地检索）

- 输入账号或客户名（原告/被告）模糊匹配，支持状态筛选（全部/审核中/立案成功/已驳回/强执成功/UNKNOWN）。
- 查询 IndexedDB 的 `cases` + `enforcementCases`，合并展示（类型列区分 立案/强执）。
- 展示字段：账号（脱敏）、原告、被告、状态、成功时间、案号、驳回时间、驳回原因（截断+悬停全文）、截图缩略图、查询时间。
- 查询时间 < 1s，纯本地，不请求平台。

## 4. 批量任务执行器（核心）

### 4.1 任务来源与分组
- 任务 = 导入模板后待查询的行（默认：本次导入的全部行；支持勾选部分行）。
- 查询类型：popup/面板选择「立案/强执」，`START_BATCH` 载荷带 `kind`（`li`/`qz`），content 按 kind 选 store（既有 `startBatch(kind)`）。
- **强执不自动切 tab**：强执批量要求用户当前停在页面顶部「执行」tab（采集器按行内 caseType 识别状态）；非执行 tab 下启动强执 → 明确提示切换。
- 按账号分组；**当前登录账号匹配到的分组为「可执行」**（与 login-module 当前账号比对 C 列）；其余分组标记「待切换账号」。

### 4.2 执行流程（单条）
```
定位该账号在平台中的案件行（列表采集器，翻页上限 10）
→ 状态识别（query-module 映射表）
→ 待审核：写状态=审核中 + queryTime=当天，不截图
→ 成功/驳回：进入详情采集 → 截图（screen-capturer）
→ 写 IndexedDB（唯一键 upsert）
→ 下一条（间隔 3–8s 随机）
```

### 4.3 控制与失败处理
- 单批上限 50 条；批间需人工确认继续。
- 失败重试 1 次（同一条）；仍失败 → 标记「待人工」并跳过，不阻塞后续。
- 会话失效事件 → 立即暂停队列，提示重新登录；恢复登录后从暂停点继续。
- `SELECTOR_CHANGED` → 暂停，提示更新选择器配置。
- 暂停/继续：popup 按钮控制；暂停点落盘（chrome.storage.local），popup 关闭重开后任务状态保留。
- 进度展示：当前条目（账号+客户名脱敏）、已完成/总数、失败数。

### 4.4 账号切换衔接
- 当前账号分组执行完毕 → popup 提示「账号 A 完成，请手动登录下一个账号（B）后点击继续」。
- 插件检测到登录账号变化（login-module）→ 自动切换到新账号分组继续（若在等待继续状态）。

## 5. 每日流程（用户操作闭环）

1. 操作人员手动登录平台（全人工）。
2. popup「导入模板」：选当天新案件模板文件 → 导入摘要展示（成功/更新/跳过）。
3. 「开始查询」：按 §4 批量执行；中途按提示切换账号。
4. 「导出报表」：生成 `立案与强执查询表-<日期>.xlsx` 下载（核心流程不变）；已配置服务器时自动上传，后台「报表导出」可再次下载；上传失败不阻塞本地导出（详见 report-export-module）。
5. （可选）软件内查询核对历史记录。

## 6. 测试

- 单测：任务分组（按账号）、节流调度（间隔范围断言）、暂停/继续状态机、失败重试与「待人工」标记、唯一键 upsert。
- simulator 集成：mock 平台页 + fake IndexedDB（node 环境）跑通「导入→批量查询→写库→导出」链路。
- 真实联调（验收闸门）：用户已登录真实会话，全流程走查 2–3 条真实案件，验收记录只写脱敏摘要。

## 7. 范围外（不做）

- 不做定时/自动执行（无 cron、无后台定时批量）——每天由操作人员手动触发。
- 不做账号自动切换/自动登录（登录全人工）。
- 不做多用户/权限体系；不做远程同步。
- 不做平台消息推送/通知中心。
- 不做数据统计图表（报表仅导出模板格式）。
