# 企业微信群机器人 Webhook 推送模块规格

## 1. 目标

查询结果对应截图成功持久化后，服务端自动向企业微信群机器人推送通知。通知包含对应证据截图、原告/被告名称、案件结果内容，并在消息正文显示 `@业务员姓名 @助理姓名`；该文本不承诺触发企业微信成员提醒，失败记录只允许后台人工重试。同一案件终态在不同的 `QUERY_ALL_EXPORT` 命令成功完成证据闭环后允许各重复推送一次。

## 2. 配置与敏感信息

- 每个系统用户可以由管理员单独配置一个企业微信群机器人 Webhook。Webhook 使用 AES-256-GCM 加密后存入 `users` 表，认证标签、随机 IV、密文和版本必须成组存在或成组为空；加密附加认证数据绑定用户 ID，禁止把一个用户的密文复制给另一个用户解密使用。
- 服务端从现有 32 字节凭据主密钥通过 HKDF 派生用途隔离的 Webhook 加密子密钥；主密钥、Webhook 明文、密文、认证标签和 IV 不得进入浏览器存储、Git、Obsidian、普通响应正文或日志。用户列表与设置/清除接口只返回 `wecomWebhookConfigured: boolean`，不得回显完整 URL、`key` 或任何密文字段。
- URL 必须为 HTTPS，主机必须精确等于 `qyapi.weixin.qq.com`，路径必须为 `/cgi-bin/webhook/send`，必须且只能含一个非空 `key` 参数，并且不得含用户名、密码、显式端口或 fragment；不允许请求任意 URL。
- 通知发送时根据案件 `createdBy` 查找对应系统用户的 Webhook。用户未配置时允许使用服务端环境变量 `WECOM_WEBHOOK_URL` 作为兼容兜底；用户清除配置后恢复使用该兜底。用户已有加密配置但解密或认证失败时必须返回安全错误并停止发送，禁止回退到系统级地址，避免案件误发到错误群。
- 业务员和助理使用显示姓名，按平台账号绑定并持久化在 `platform_accounts`；后台普通列表仅返回是否已配置，只有管理员编辑接口可写入，接口和日志不回显完整姓名。
- 已有企业微信 UserID 字段通过可回滚迁移原样改名为姓名字段，以保留当前已填写的中文姓名；旧版手机号绑定只作为迁移兼容数据保留，通知服务、后台接口和表单不得读取、回显或发送旧手机号。
- 真实案件名称、案号、结果内容和截图仅发送到用户配置并主动触发的目标企业微信群；自动化测试只能使用脱敏合成数据。

## 3. 入口与权限

- 后台“系统用户”页为每个用户提供“配置群机器人”和“清除配置”操作，并显示“已配置”“未配置”或“使用系统兜底”；页面与脚本不得包含或请求现有 Webhook 明文。
- 设置接口为 `PUT /users/:id/wecom-webhook`，请求体仅接受 `{ webhookUrl: string }`；清除接口为 `DELETE /users/:id/wecom-webhook`。两个接口只接受管理员 Cookie 会话与有效 CSRF，扩展 Bearer、普通用户和匿名请求均拒绝；目标用户不存在时返回稳定的未找到错误。
- 后台平台账号管理页为管理员提供“业务员姓名”“助理姓名”绑定字段；两个字段必须同时配置或同时清空。
- 截图上传接口完成案件与截图落库后，必须先成功创建或确认幂等通知台账再返回成功，防止截图已成功但后台没有通知记录；新通知必须在同一次数据库写入中显式保存初始状态 `pending`，不得依赖表字段默认值。实际网络推送继续异步执行，推送失败只更新通知记录为 `failed`。通知台账创建失败时上传请求返回失败，客户端可凭同一截图幂等重试并补建台账。
- 上述异步发送不等于一键任务成功：`QUERY_ALL_EXPORT` 回写终态只核验案件同步与终态截图已入库；`pending`、`sending` 或 `failed` 通知保留在通知台账并按既有入口人工重试，不得改写为 `EVIDENCE_NOT_CLOSED` 或阻止报表生成。
- `QUERY_ALL_EXPORT` 首次成功写入终态后，服务端为该命令涉及的每条既有终态证据创建一条独立的重复推送记录并异步发送。同一命令的重复完成回执不得重复创建或发送；新的查询导出命令允许再次推送。重复推送是命令成功后的附加发送，不反向改变已经完成的报表命令状态；失败记录进入现有人工重试流程。
- 人工重试接口为 `POST /wecom-notifications/:id/retry`，只接受后台 Cookie 会话与有效 CSRF；扩展 Bearer、匿名请求和越权访问均拒绝。
- 用户和系统级 Webhook 均未配置时页面可保留入口，但发送返回稳定错误 `WECOM_NOT_CONFIGURED`，不得把配置值返回客户端。

## 4. 消息内容与顺序

1. 仅 `立案成功`、`强执成功`、`已驳回` 三种终态进入自动推送；从服务端案件记录读取平台账号、原告、被告、案件类型、状态、案号、驳回原因和查询时间，禁止由客户端提交或覆盖这些业务字段。
2. 按结果选择截图：`已驳回` 使用 `reject`；立案成功使用 `success`；强执成功使用 `enforcement_success`。没有对应截图时停止并返回 `WECOM_SCREENSHOT_MISSING`，不发送无图通知。
3. 图片从私有对象存储读取，转换为企业微信 `image` 消息要求的 Base64 与 MD5。原始图片超过企业微信 2 MiB 限制时返回 `WECOM_IMAGE_TOO_LARGE`。
4. 先发送图片，再发送一条 `text` 消息。文本第一行固定为业务员与助理姓名各自添加 `@` 前缀并以空格分隔，重复姓名去重；后续至少包含案件类型、原告、被告、结果、案号（存在时）、驳回内容（存在时）和查询时间（存在时）。文本载荷不得包含 `mentioned_list` 或 `mentioned_mobile_list`，因此 `@姓名` 仅作视觉提示，不承诺触发企业微信提醒。
5. 企业微信返回 HTTP 非成功、非 JSON、`errcode != 0` 或网络失败时记录稳定错误码 `WECOM_DELIVERY_FAILED`；不得持久化或向客户端、日志透传 Webhook、响应正文、联系人姓名或案件明文。图片成功而文本失败属于失败，操作员核实群内情况后可人工重试。
6. 通知唯一键为 `(case_id, result_status, trigger_id)`：首次终态截图上传以 `screenshot_id` 作为触发 ID；成功完成证据闭环的 `QUERY_ALL_EXPORT` 以 `browser_command_id` 作为重复推送触发 ID。相同截图重传、同一命令重复回执、服务重启或并发请求均不得重复发送；不同查询导出命令允许对相同案件终态再次推送。状态将来从一个终态变为另一个终态时，允许按新结果产生通知。
7. 发送前必须再次校验案件当前结果仍等于通知结果、截图仍属于该案件且截图类型与当前结果一致；任一来源已变化时以 `WECOM_SOURCE_CHANGED` 失败，不得混用旧截图与新结果文本。
8. 通知记录只持久化案件 ID、平台账号 ID、结果状态、`pending/sending/sent/failed`、安全错误码、尝试次数及时间；不保存消息正文、截图 Base64、联系人姓名、Webhook 或企业微信响应。

## 5. 输入校验与节流

- 平台账号的两个联系人姓名必须同时填写或同时清空；填写时去除首尾空白，长度为 1–64 个字符且不得包含控制字符。
- 用户级 Webhook 设置时必须先完成 URL 白名单校验再加密持久化；空字符串不能代替清除操作。非法 URL 返回稳定校验错误，错误详情不得包含用户提交的 URL。
- Webhook 未配置、联系人未配置、案件非三种终态或对应截图缺失时不访问企业微信；联系人未配置时创建 `failed/CONTACTS_NOT_CONFIGURED` 记录，供配置后人工重试。
- 每条首次或重复推送通知自动尝试 1 次；没有后台定时器、队列轮询或失败自动重试。每次人工点击重试只增加 1 次尝试并重新发送一次，按钮提交期间禁用。

## 6. 范围外

- 企业微信自建应用、智能机器人插件、群聊管理、通讯录查询、UserID/手机号发现、真正的企业微信成员提醒、失败自动重试、定时批量推送。
- 修改法院状态映射、截图采集规则、案件数据结构、报表导出格式。

- TDD 覆盖用户级 Webhook 迁移与回滚、成组字段约束、AES-256-GCM 加密与用户 ID 绑定、设置/清除、URL 白名单、管理员 Cookie+CSRF 权限、拒绝普通用户/扩展 Bearer/匿名访问、用户列表及接口不泄漏 URL/key/密文、案件按 `createdBy` 发送到各自地址、未配置用户使用系统级兜底、清除后恢复兜底、密文损坏时停止且不误用兜底、后台配置入口与安全错误展示。
- TDD 覆盖迁移保留现有联系人值并可回滚、重复推送触发 ID 迁移与回滚、旧手机号不再启用联系人、PostgreSQL 通知仓库显式写入 `pending`、姓名成对绑定与脱敏、姓名校验、三种终态触发、非终态跳过、相同触发 ID 并发唯一去重、不同查询命令允许重复推送、同一命令完成回执幂等、重启幂等、Base64/MD5、正文首行显示去重后的 `@姓名` 且载荷无 `mentioned_list`/`mentioned_mobile_list`、失败记录、无失败自动重试、人工重试权限和企业微信错误脱敏。
- `npm run server:build` 与 `npm test` 通过。
- 仓库敏感信息扫描确认无真实 Webhook key、手机号、联系人姓名、案件名称、结果截图或响应正文。
