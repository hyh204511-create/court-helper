# 企业微信群机器人 Webhook 推送模块规格

## 1. 目标

后台案件详情页允许当前有权查看案件的 `admin` 或 `user` 手动发起一次企业微信群机器人通知。通知包含与当前结果对应的证据截图、原告/被告名称、案件结果内容，并同时 `@业务员` 与 `@助理`。

## 2. 配置与敏感信息

- Webhook 仅从服务端环境变量 `WECOM_WEBHOOK_URL` 读取，不进入数据库、浏览器、Git、Obsidian、响应正文或日志。
- URL 必须为 HTTPS，主机必须精确等于 `qyapi.weixin.qq.com`，路径必须为 `/cgi-bin/webhook/send`，且必须含非空 `key` 参数；不允许请求任意 URL。
- 业务员和助理使用企业微信可识别的手机号，由操作员在单次推送表单中填写；仅在该请求内存中使用，不落库、不写日志、不回显到响应。
- 真实案件名称、案号、结果内容和截图仅发送到用户配置并主动触发的目标企业微信群；自动化测试只能使用脱敏合成数据。

## 3. 入口与权限

- 后台案件详情页提供“推送到企业微信群”表单，包含业务员手机号、助理手机号和二次确认提示。
- 接口为 `POST /cases/:id/wecom-notifications`（同时提供 `/api/v1` 前缀版本），只接受后台 Cookie 会话与有效 CSRF；扩展 Bearer、匿名请求和跨用户案件访问均拒绝。
- Webhook 未配置时页面可保留入口，但提交返回稳定错误 `WECOM_NOT_CONFIGURED`，不得把配置值返回客户端。

## 4. 消息内容与顺序

1. 从服务端案件记录读取原告、被告、案件类型、状态、案号、驳回原因和查询时间，禁止由客户端提交或覆盖这些业务字段。
2. 按结果选择截图：`已驳回` 使用 `reject`；立案成功使用 `success`；强执成功使用 `enforcement_success`。没有对应截图时停止并返回 `WECOM_SCREENSHOT_MISSING`，不发送无图通知。
3. 图片从私有对象存储读取，转换为企业微信 `image` 消息要求的 Base64 与 MD5。原始图片超过企业微信 2 MiB 限制时返回 `WECOM_IMAGE_TOO_LARGE`。
4. 先发送图片，再发送一条 `text` 消息。文本至少包含案件类型、原告、被告、结果、案号（存在时）、驳回内容（存在时）和查询时间（存在时）。`mentioned_mobile_list` 同时包含业务员与助理手机号，去重但不得使用 `@all`。
5. 企业微信返回 HTTP 非成功、非 JSON、`errcode != 0` 或网络失败时返回稳定错误 `WECOM_DELIVERY_FAILED`；不得向客户端或日志透传 Webhook、响应正文、手机号或案件明文。图片成功而文本失败属于部分送达，接口仍返回失败，操作员可人工确认后重试。

## 5. 输入校验与节流

- 两个手机号均必填，去除首尾空白后必须匹配中国大陆手机号格式 `1` 开头的 11 位数字；字段外内容拒绝。
- 单次请求只允许推送一个案件和一张对应截图，不提供批量推送或自动触发。
- 提交期间前端禁用按钮，成功后仅显示“已推送”，不在页面持久化手机号。

## 6. 范围外

- 企业微信自建应用、智能机器人插件、群聊管理、通讯录查询、手机号自动发现、消息回执持久化、失败自动重试、定时推送、无人值守批量推送。
- 修改法院状态映射、截图采集规则、案件数据结构、报表导出格式。

## 7. 验收闸门

- TDD 覆盖权限隔离、CSRF、配置 URL 校验、手机号校验、结果截图选择、Base64/MD5、文本字段、双人 @、缺图、超限、企业微信错误脱敏。
- `npm run server:build` 与 `npm test` 通过。
- 仓库敏感信息扫描确认无真实 Webhook key、手机号、案件名称、结果截图或响应正文。
