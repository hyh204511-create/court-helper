# 规格：平台账号 Excel 导入

## 目标

在后台“平台账号”页面提供一次性导入 Excel 的能力，导入结果与逐条填写“显示标签、平台账号、平台密码、业务员姓名、助理姓名”后保存一致。业务员和助理是平台账号级固定联系人，不是仅用于某次报表的临时字段。

## 输入

- 仅接受 `.xlsx`，只读取 `Sheet1`。
- 第 1 行必须包含 A-D 列标题：`原告`、`被告`、`账号`、`密码`；被告仅用于兼容模板，不写入平台账号。
- 旧版使用范围不超过 T 列的模板继续允许导入账号但不配置联系人。使用范围到达 U/V 列时必须同时具有 U=`业务员`、V=`助理` 的精确表头；只存在一列或表头不匹配时拒绝整份文件，禁止静默忽略联系人列。
- 从第 2 行开始读取：A 列原告作为显示标签，C 列作为平台账号，D 列作为平台密码。
- 对带 U/V 表头的模板，同一行 U/V 首尾空白清理后分别作为该平台账号固定的业务员姓名和助理姓名。两列必须同时填写或同时为空；单边缺失的行跳过并返回稳定原因。姓名各自最长 64 个字符且不得含控制字符，不合规行跳过。
- 完全空行跳过；标签、账号或密码任一为空的行跳过并返回行号原因。
- 单次最多 2000 行；超过上限拒绝整份文件。

## 行为

- 仅管理员后台会话可调用；使用 multipart 上传，不把凭据放入 URL、日志、响应或浏览器持久化状态。
- 每个有效行调用与单条创建相同的加密保存逻辑，默认启用，并把有效 U/V 姓名成对写入 `platform_accounts.salesperson_name / assistant_name`。
- 标签已存在时跳过该行，不覆盖原账号密码；其它行继续处理。
- 返回 `{ imported, skipped, reasons[] }`，`reasons` 仅含行号和稳定错误码，不含账号、密码或原告明文。
- 稳定逐行原因至少包括：基础字段缺失 `REQUIRED_FIELD`、联系人只填一侧 `CONTACT_PAIR_REQUIRED`、联系人格式不合法 `INVALID_CONTACT_NAME`、标签重复 `DUPLICATE_LABEL`。
- 管理员读取平台账号列表时返回并展示业务员和助理姓名；普通用户列表仍只返回 `contactsConfigured`，不得取得联系人姓名。创建、编辑、删除的单条响应不回显姓名。
- 原有单条新增、编辑、启停、软删除流程保持不变。

## 范围外

- 不修改原始 Excel。
- 不导入被告或案件数据。
- 不支持多工作表、CSV、批量覆盖或批量删除。
- 不把 U/V 复制到案件、浏览器命令、报表元数据、日志或错误详情。

## 删除后重导入闭环

- 平台账号删除保持软删除，历史案件和任务仍引用旧记录。
- 标签唯一性只约束未删除记录；同标签存在未删除账号时仍逐行跳过。
- 软删除后再次导入相同“原告”标签时，必须创建新的启用账号并使用新账号密码，不能被旧记录判为重复。

## 验收

- 22 列合并报表导入后，平台账号仓库中的联系人姓名与同一行 U/V 一致，且管理员列表显示两人的姓名。
- 旧版不含 U/V 的账号模板保持可导入，联系人状态为未配置。
- 单边联系人、超长或含控制字符的姓名逐行跳过且响应不泄露业务明文；U/V 表头只出现一列或写错时拒绝整份文件。
- admin 列表可见姓名，user 列表和单条写操作响应不可见姓名。
