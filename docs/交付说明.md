# 法院立案/强执查询助手 — 交付说明（给老板）

> 本文档写给不写代码的人看。只讲三件事：这个工具怎么帮你干活、现在做到哪了、下一步做什么。
> 项目代号：court-helper（法院查询助手）

---

## 一、这是什么

**一句话：一个装在浏览器里的"自动查询小助手"，每天帮你在法院网站上一案一案地查立案和强制执行的状态，把结果、时间、案号、截图自动填回你现有的 Excel 表格里。**

你现在的日常工作是这样的：
1. 登录法院网站 → 一个账号一个账号地登录
2. 找到某个客户/当事人的案件 → 看状态（立案成功？被驳回？还在审核？）
3. 手工把状态、时间、案号抄进表格
4. 对"驳回"和"立案成功"的还要截图，再把图片一张张贴进表格单元格

这个助手把第 2～4 步自动化：你只管**登录账号**（安全考虑，登录必须人工），其余查询、判断、抄写、截图、填表全部自动完成。

---

## 二、它是怎么帮你干活的（需求实现方式）

### 1. 登录：还是你亲手来，但助手会"看着"

- 助手**不帮你填账号密码、不点登录**（防止账号风险，这是特意设计的）。
- 你登录后，助手能认出"当前登录的是哪个账号"，并且**只查这个账号名下的案件**——账号对不上会停下来提醒你，绝不拿 A 账号的截图填到 B 客户的表格里。

### 2. 查状态：自动逐案查询，状态识别"宁可不知道，绝不瞎猜"

- 从你导入的表格里读出每个案件（原告、账号、类型）。
- 到法院网站的案件列表里找到这个案件，读状态：
  - **待审核** → 表格里记"审核中"，记下查询时间，不用截图；
  - **已立案**（民事案件）→ 表格里记"立案成功"；
  - **待补充材料 / 审核不通过 / 不予立案** → 表格里记"已驳回"；
  - **遇到没见过的状态** → 表格里记"待人工处理"并标红提醒，**绝不猜一个状态写进去**（这是本项目最重要的规矩：状态错了比没查到更糟）。

### 3. 抄数据：驳回和成功的取证内容不同

- **驳回案件**：自动进详情页读"审核时间"（精确到秒，写表时只取日期）和"审核意见"（驳回原因全文），填进表格的"驳回时间""驳回原因"两列；同时对审核结果页面**自动截图**，嵌入表格"驳回图片"那一格。
- **立案成功案件**：自动从"我的案件"里读**案号**和**立案日期**（=立案成功时间），填进"案号""立案成功时间"两列；对成功页面**自动截图**，嵌入"成功图片"那一格。

### 4. 强执（强制执行）查询：和立案同样的一整套

- 在"我的案件"页面顶部切换到"执行"栏（相当于你平时说的"查看强执"）。
- 状态"已立案"或"已结案" → 表格记**"强执成功"**，读**强执案号 + 强执成功时间**，截图嵌入"成功图片"格；
- 驳回/待审核的流程与立案完全一致。

### 5. 表格导入导出：完全按你现在的格式

- **导入**：把你每天发来的新案件表格（还是你现在用的那个格式）导进去，助手识别"立案表"和"强执表"两个区域，逐行入库；格式不对会明确提示哪一行有问题。
- **导出**：一键导出一份和模板**一模一样格式**的表格（含表头样式、日期格式、双表区域），状态、时间、案号、原因、截图图片全部嵌入对应单元格，发给你或发给别人直接用。
- 你表格里"密码"那一列：助手**只读、不修改、不导出**（密码只用来匹配账号，绝不落盘）。

### 6. 软件内查询：不用翻表格

- 在助手面板里输入**账号**或**客户名字**（或选状态），立刻列出所有匹配案件：账号、客户、类型、状态、成功时间、案号、有没有截图、查询时间。状态是"待人工"的会带 ⚠ 标记。

### 7. 每天批量干活

- 面板点"开始查询"，助手按顺序逐案处理，自动在案件之间停 3～8 秒（模拟人工节奏，不触发网站风控），单批最多 50 条；
- 某个案件查询失败会自动重试 1 次，还不行就标记"待人工"，**不会卡住整批**；
- 查询过程中页面右上角会实时显示进度。

## 三、项目是怎么开发出来的（开发方式）

为了保证可靠，这个项目用了一套"稳扎稳打"的开发流程：

1. **先写说明书再写代码**：每个功能先写《规格说明》（这一功能做什么、不做什么、边界在哪），说明书没定稿不动代码；
2. **小步走、步步验证**：一个功能一个功能做，每个功能先写测试（机器自动检查代码对不对），测试通过了才提交存档；
3. **不猜平台**：法院网站的页面结构是**用三个真实账号登录实测确认**的（一个"待补充材料"账号、一个"已立案"账号、一个"强执成功"账号），每条规则都有真实页面印证，不确定的地方一律标"待人工"；
4. **数据安全**：真实客户资料、身份证号、案号、截图只在你本机产生，不进入代码库、不联网上传；代码库里只有脱敏的模拟数据（测试用）。

目前自动化测试 **58 项全部通过**，涵盖：状态识别、列表读取、详情读取、批量调度、重试机制、表格导入导出（含图片）、模拟页面端到端验收。

2. **收尾打磨**：根据验收结果微调（比如某些文案、时间格式、页面小变化）；
3. **打包安装**：生成安装包，加载到你的浏览器（Edge/Chrome），教会你日常使用：导入 → 点查询 → 导出；
4. **上线后维护**：法院网站偶尔改版，助手有"结构变了自动提醒"机制，届时更新配置即可，不用重做。

## 六、还需要你确认/对接的细节

1. **批量查询时账号怎么切**：因为登录必须是人工的，批量查询按"当前登录账号"分组执行——同一批里如果含多个账号的案件，需要你中途切换账号（助手会提示）。请确认这个操作方式是否符合你的习惯，或者你希望调整成"一次只处理一个账号"的模式；
2. **"待审核"案件**：目前设计是只记状态和时间、**不截图**。如果你希望审核中也截图留档，告诉我，一行配置就能加；
3. **驳回原因里可能含客户隐私**（如住址、身份证号），导出表格时这些内容原样保留（和现在手工填的一致）——请确认导出文件的分发范围；
4. **"审核通过"等罕见状态**：目前一律标"待人工"等你确认怎么归类，遇到时告诉我一次，以后就自动了；
5. **查询频率**：目前每案间隔 3～8 秒、单批 50 条。如果案件量很大（比如一天几百条），可能需要调整节奏，请确认日常量级；
6. **最终装哪个浏览器**：默认 Chrome/Edge 都支持，确认一下你平时用哪个。

## 附：技术概况（简单了解即可，不用细看）

- 形态：浏览器扩展插件（Edge/Chrome 通用），不需要安装任何其他软件；
- 工作方式：在你已登录的法院页面上自动读取页面信息（不读取你浏览器里其他网站的任何数据），截图直接存在你本机；
- 数据存储：全部在你本机浏览器里，不经过任何服务器；
- 开发语言/框架：JavaScript + 少量 Python 测试工具；表格处理用开源 Excel 库，保证与 WPS/Excel 兼容；
- 代码托管：本地 Git 仓库，按"规格先行、测试驱动、原子提交"方式管理，每一步都有记录可回溯。
